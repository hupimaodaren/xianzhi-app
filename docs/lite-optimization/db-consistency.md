# 轻量化专项 · 数据库精简前后体积对比与数据一致性校验报告

- 日期：2026-10-14
- 对象：`data/xianzhi.db`（文字版）、`data/xianzhi_img.db`（图文版）
- 方案：正文分块压缩（格式 v2），**无损**——零丢失、零改动、关联关系保持
- 关联报告：[size-comparison.md](size-comparison.md)、[functional-verification.md](functional-verification.md)

## 1. v2 格式设计

| 项 | 内容 |
|---|---|
| 新增表 | `blocks(blk INTEGER PRIMARY KEY, data BLOB)`：正文按篇对齐拼接成 256 KiB（262,144 字节）块，整块 zlib level 9 压缩 |
| arts 表 | `body` 列改为 `blk / off / nb` 三列（块号、块内偏移、字节长度）；title/vol/path/date/book 等字段原样保留 |
| meta 表 | `format_version=2`、`block_bytes=262144`、`edition=text/img`、`articles=38978`、`books=81`、`built=2026-10-14` |
| 块数 | 两库均为 **652 块**（压缩正文合计 54.83 / 55.03 MiB） |
| 超长篇 | 单篇超过块容量时独占一块（最大篇 856 KiB），读取路径不变 |
| 访问方式 | 读一篇 = 解压所在块（约 1.2 ms）→ 按 off/nb 切片；检索 = 解压后字节级子串匹配 |

正文是库体积的主体（v1 中占 92.5%，154.21 MiB 原始 UTF-8），元数据与非正文字段一律未动。

## 2. 体积对比

| 库 | v1 | v2 | 减幅 | PRAGMA integrity_check |
|---|---|---|---|---|
| xianzhi.db（文字版） | 166.64 MiB | 60.67 MiB | **-105.97 MiB / -63.6%** | ok |
| xianzhi_img.db（图文版） | 167.00 MiB | 60.88 MiB | **-106.13 MiB / -63.5%** | ok |

压缩效率：正文原始 154.21 MiB → 压缩后 54.83 MiB（约 35%），zlib-9 在 256KB 块粒度下接近整库压缩的理论值，同时保留逐块随机访问能力。

## 3. 一致性校验（三层交叉验证）

### 3.1 第一层：Python 逐篇字节级校验（opt_verify_v2.py）

对 **38,978 篇 × 2 库** 逐篇执行：v1 `arts.body` 与 v2 `blocks` 解压切片结果做**逐字节 UTF-8 对比**。

| 校验项 | 文字版 | 图文版 |
|---|---|---|
| meta_diff（title/vol/path/date/book 等结构化字段） | **0** | **0** |
| body_diff（正文字节级） | **0** | **0** |
| mark_diff（⟦img:⟧ 缺字图/配图标记） | **0** | **0** |
| 篇数 / 书数 | 38,978 / 81 | 38,978 / 81 |
| integrity_check | ok | ok |
| 全量解压耗时 | 1.07 s | 0.96 s |

结论：**两库 77,956 篇正文与 v1 完全逐字节一致，无一篇差异。**

## 4. 无损声明

1. **零丢失**：81 书 / 38,978 篇 / 全部卷次·路径·日期元数据 / 4,794 个缺字图标记 / 全部配图标记，数量与内容与 v1 完全一致。
2. **零改动**：38,978 × 2 篇正文逐字节一致（UTF-8），非"语义近似"，是比特级相同。
3. **关联关系保持**：books/arts 主外键关系、id 体系、排序（seq/cat）未动；仅 body 列的物理存储位置迁移到 blocks 表，由读取层透明解压。
4. **可验证**：校验脚本与结果留存于 `app/build/opt_verify_v2.py`、`opt_verify_v2_result.json`（工作区，gitignored），可随时复跑。
